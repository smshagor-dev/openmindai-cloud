# Openmindai feature coverage

Openmindai is an independent self-hosted chat application. This implementation reproduces selected familiar workflows; it is not complete ChatGPT product parity. Local inference uses the administrator's own runtime and Hugging Face downloadable models. Optional interactive NVIDIA Nemotron hosted chat is available through the Next.js server, with Laravel DB persistence; see [NVIDIA setup](NVIDIA_FRONTEND_CHAT.md). Background tasks/media retain their self-hosted runtimes.

## Hosted and self-hosted media integrations

Media studio supports hosted image generation, English speech-to-text, speech audio synthesis, PDF/Word document generation and short Cosmos video generation through the server-side Next.js NVIDIA integration with private Laravel task storage. Existing separately configured local image generation, image understanding, audio transcription, speech generation, Wan video generation and PDF/DOCX text extraction remain available. Includes task ownership, quotas, status/failure handling, private previews/downloads, deletion and reuse of text in chat. The Laravel/Next workflows and Python HTTP contract are tested with fixtures. Hosted media integrations include simulated API and access-control tests but have not yet been verified against live provider services on a deployed host; real local model/GPU inference also remains unvalidated in this environment. Self-hosted media kinds remain disabled until the administrator provisions compatible revision-pinned HF snapshots, runs the private Python runtime and queue worker, and enables the kinds. Hosted media creation needs a private Next.js NVIDIA_API_KEY, matching shared frontend/backend bridge secret, per-model API access and Laravel migrations; see HOSTED_IMAGE_API.md and HOSTED_MEDIA_API.md. Generated DOCX preserves Unicode; the lightweight PDF exporter supports Latin text only and rejects unsupported scripts. See [runtime setup](../runtime/media/README.md). Admins can now inspect/import/download checksum-verified safetensors/config/tokenizer snapshots at `/admin/model-bundles`; CLI provisioning remains available. A compatible runtime still needs to be deployed separately.

## Not implemented

The following are absent, rather than simulated by buttons: native duplex audio/video model inference, team-member video calls, autonomous browser agents, arbitrary interactive analysis notebooks, paid assistant commerce, connected-account OAuth and character-level simultaneous document co-editing. Implemented Teams, token-based MCP and chained live voice/frame workflows are described in [collaboration and live setup](COLLABORATION_AND_LIVE.md). Billing/subscriptions/payments are excluded by request. Bounded research, scheduled tasks and an optional reviewed Python runner are described below. These require separate implementation, secure execution environments, suitable self-hosted engines/models and deployment capacity. Downloading a GGUF file does not provide those capabilities.

The read-aloud feature and queued speech generation are not realtime voice chat. Canvas is a text/document editor, not a browser or code-execution sandbox. Search snippets are not a verified multi-page research report. Memory supports explicit notes and opt-in model extraction from completed chats, with user review/deletion; see [workspace additions](WORKSPACE_FEATURES.md).

## Privacy and operational details

The streaming endpoint saves a user question and a generating assistant record before contacting inference. Completed, failed and stopped responses remain in history, including any partial text. A stream terminated by a process crash can remain generating until scheduled cleanup marks it failed after ten minutes. The older non-streaming `/chat` endpoint keeps its atomic success-only storage behavior.

Temporary chat sends its in-memory previous turns back to the runtime without creating chat records. Files uploaded to the separate library are still stored until explicitly deleted; selecting temporary chat does not delete existing library files. Export/share are opt-in user actions. Share snapshots contain completed message text, not raw library file contents or authentication secrets; users should still review what their message text reveals.

A stop request needs a second available PHP worker while the streaming worker is active. Disable response buffering for SSE at the reverse proxy. A slow/buffered server can delay deltas and cancellation. An inference runtime must support chat-completion SSE; there is no fake typewriter fallback. Actual inference, hosting, SMTP, browser voice and visual/responsive QA require deployment-specific validation.

## Profile and settings

The Settings dialog now groups General, Personalization, Data controls, Account, Security and Devices. General settings persist theme (including live system-theme changes), accent color, chat text size, reduced motion, Enter-to-send and optional hidden-tab completion notifications. Browser notifications require permission on each supported desktop browser; no background/mobile push service is included. Response language affects inference instructions, not translated interface labels.

Account settings include display name, locally resized profile photo, verified email-change workflow, password change, TOTP/recovery codes and current-device identification/revocation. Email changes keep the existing address active until explicit single-use confirmation at the new address (one-hour expiry); confirmation revokes tokens and server sessions. Password changes/reset cancel pending email changes. SMTP and a correct `FRONTEND_URL` are required. Photos are stored in the user's DB record as validated PNG/JPEG/WebP data URLs, never SVG or arbitrary remote URLs.

Personalization includes nickname, occupation, background, custom instructions, response style/detail/language, a customization switch, independent memory opt-in and memory CRUD. These choices are injected into future saved-chat inference contexts. Temporary chat excludes personal customization and memory.

Data controls include export with profile/preferences, paginated archived-chat restoration/deletion, share revocation, bulk archive/delete chats, clear all memories, revoke all shared links, and account deletion. Bulk actions require a typed action confirmation plus password and enabled 2FA. Account deletion requires password/2FA; the frontend also requires typing the account email. Deleting chats removes messages/share snapshots; independent library files, media tasks, canvases and memories remain until separately deleted or the account is deleted. Infrastructure backup retention is controlled by the host operator. No training, billing, subscription, connected-app, parental-control or enterprise-admin product is implemented by these settings; there are no pretend toggles for absent services.

## Workspace tools UI

The Tools & library workspace adds private assistant creation/editing/deletion, model selection and up to five owned text knowledge files. Assistant instructions are carried into saved conversations and their branches. Private assistants can be explicitly published as public instruction snapshots in `/explore`; users can preview/copy them without inheriting files or model settings, and admins can block publications. This is not a paid marketplace.

Tasks support manual runs and one-time/daily/weekly scheduling, edit/pause/delete, paginated run history, progress steps, cancellation and downloadable results. Research starts with three searches, eight sources and six page reads, then uses a model coordinator to continue searching/reading until its coverage decision without a fixed iteration/source count. The page reader uses public HTML/text pages with DNS pinned to validated public addresses. Redirects/private targets are rejected. Reports include citations and source summaries/read status; extracted full page text is excluded from source summaries but retained in encrypted recovery checkpoints until successful completion or deletion. See [research setup](WEB_RESEARCH.md) for limits and interactive NVIDIA support. It is evidence-gathering research, not a general browser operator or a guarantee of factual verification. Background local runs support encrypted checkpoints and owner-controlled resume; saved interactive NVIDIA responses support encrypted checkpoints and explicit resume of the latest interrupted turn without another daily request. Native local interactive streams still lack crash resume. A cancelled active HTTP inference may finish server-side; its result is discarded.

Library combines searchable, paginated text files and media tasks, type filters, text/image/audio/video previews, private downloads, deletion and reuse in chat. Composer supports drag/drop and local image/PDF/audio preview before submitting to owned media tasks; DOCX becomes extracted text after processing. Media creation modes produce inline preview cards, and results remain in the Library. Inline preview placement is local to the current browser workspace view, not persisted as multimodal message blocks in chat history.

Voice input provides microphone permission, a live level meter, stop, queued private transcription and editable transcript before sending. It is turn-based. The separate Live tab adds continuous listening and sampled camera/screen analysis, with private runtime setup; it is not a native duplex audio/video model. Canvas now supports simultaneous editor/preview, lexical code highlighting, retained versions (latest 50), side-by-side comparison and loading an old version into a new draft. Comparison is side-by-side text, not a full semantic/line-level diff editor. A branch navigator lets users switch saved conversations in the same owned branch family.

The Python/data panel requires explicit code review/approval before submitting to an optional isolated container runner. It shows output and downloads an artifact ZIP; it does not execute code in the web application or offer live interactive charts. See runtime setup. General autonomous tool-calling/browser agents and connected-account OAuth remain separate product work. Team collaboration and reviewed token-based MCP tools are now available; billing is excluded by request. No disabled service is represented as a working commercial feature.

Deployment: migrate the DB, restart workers, run `php artisan queue:work --queue=tasks --timeout=0 --tries=1` alongside existing queues and run the scheduler every minute. Research requires the configured self-hosted SearXNG endpoint and PHP cURL/DOM extensions. Voice recording requires HTTPS and browser microphone permission. All newly added engine features remain gated by actual server configuration. Browser visual/device QA, real microphone recording, GPU output, Docker isolation and public-page extraction on the deployed network remain acceptance checks.


## Voice/screen controls and code artifact previews

Voice input adds hardware-track mute/unmute, discard recording and cancellation guards for pending microphone permission. Screen preview uses the browser's explicit tab/window/display chooser and stops all tracks on close/end. Preview frames stay local; only “Send one screenshot” sends a bounded single JPEG to the private vision queue. The separate Live tab supports continuous voice turns and sampled screen/camera observations; this preview remains a single-frame workflow. HTTPS, browser permissions and the enabled transcription/vision runtimes are required; physical microphone/display-capture validation remains a device acceptance check.

The isolated Python runner now creates allowlisted artifact previews outside the execution container: PNG images, bounded CSV rows and text snippets. Laravel independently validates them and stores the previews with the owned media task. Code cards, Media studio and Library can show image previews, sortable CSV tables and a basic interactive numeric-column plot. Previews show at most 100 data rows and 30 columns; download the ZIP for full files. HTML/SVG is not rendered. Archive entry size/count, image dimensions, cell lengths and total preview bytes are bounded. Library listing omits bulky preview data; task detail retrieves it when needed. The upload admission reserve is 25 MB per active task, allowing room for binary output and previews. Existing tasks without preview metadata still support ZIP downloads. Live GPU/Docker execution and visual browser/device QA remain unverified in this environment.
