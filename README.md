# Web search and deep research

Set Laravel `SEARXNG_SEARCH_URL` to your own SearXNG `/search` URL with JSON format enabled, then refresh Laravel config and restart workers. The search buttons appear when the backend advertises this capability. Search queries leave the app for that search service and its configured search engines. No paid search API or public SearXNG fallback is bundled.

In the chat composer, choose **Web search** for one search and a concise answer from snippets, or **Deep research** for request-driven evidence gathering and a report. Choose any time, past day, week, month or year. Engine support determines freshness filtering; retrieval date is not publication date.

Deep research starts with a bounded seed batch: three complementary queries, up to eight unique URLs and up to six page reads. Those are batch sizes, not total request limits. A model coordinator then identifies missing evidence and requests further searches/reads until it decides the user's request can be answered, with any remaining limitations disclosed. There is no app-imposed iteration count or total source count. Search responses come in batches of up to ten results. Source URLs are deduplicated; malformed actions or a repeated identical action fail explicitly rather than claiming the request was fulfilled. The model's completion judgment can be wrong and is not factual verification.

Individual search requests time out after eight seconds, page requests after six seconds, and the initial batch has a 45-second work budget. Later individual provider requests have network timeouts. Per-page extraction/download and protocol-frame size guards remain. There is no overall app research deadline. Host duration, model context, database size and provider quotas remain physical/external limits; an interrupted request is failed/cancelled, not complete. A provider response ending at its output-token boundary is continued with another request and combined into the same answer. Repeated identical continuation text is treated as lack of progress. Planner calls and continuations consume provider usage.

Hosted chat requests use the admin-selected **Next.js server → Laravel → NVIDIA** or **Next.js server → NVIDIA** route with private server-side keys. See [chat access and previews](docs/chat-preview-and-guest-access.md) for guest limits, conversation URLs and document previews. Laravel remains connected for authentication, research sources, quotas, chat checkpoints, persisted answers and private media storage. The browser only calls the same-origin Next.js API. For Vercel setup, see [Frontend deployment](docs/VERCEL_DEPLOYMENT.md). Full extracted page text is sent as model context and excluded from public source summaries. It can be retained in encrypted recovery checkpoints for interrupted saved research until completion or chat deletion. Existing local models support the same interactive research mode. Temporary chats retain their existing no-message-storage behavior.

The model is instructed to cite supplied URLs next to supported claims, distinguish conflicting evidence and explain gaps. These prompts do not guarantee factual accuracy or prevent every prompt-injection attempt. Source cards show actual retrieval status independently of generated claims. Chat reports can be downloaded as Markdown with a source-evidence appendix. Search snippets are never presented as full-page verification. The page reader retains public-IP validation, pinned DNS, bounded downloads, content-type restrictions and rejection of redirects/private networks. JavaScript-rendered sites, login pages, PDFs and blocked sites may remain unreadable.

The Research workspace uses the same completion-driven policy on the configured local inference model for background runs, with progress, cancellation and Markdown download. Local interactive chat also supports this loop. The local model must reliably return the documented JSON planning actions; malformed output fails explicitly. NVIDIA planning/generation remains on the Next.js server; backend search/read tool endpoints require the live owned lease and shared server secret and are never exposed through the browser proxy. Source summaries are updated as research progresses and saved with the final or partial answer.

During NVIDIA research, backend heartbeats renew the ten-minute operational lease and keep the generating message active. Per-user locks coordinate generation; abandoned hosted/local-stream locks can be reclaimed after ten minutes without a heartbeat. Their storage TTL is one day. This is operational retention, not a guaranteed one-day runtime. Temporary mode still saves no chat/message text. Saved interactive NVIDIA chats now support explicit Resume response from encrypted database checkpoints. Research saves around each search/read; answer streaming checkpoints roughly every two seconds and at continuation boundaries. Recent unsaved deltas can still be lost on a process crash. Only the latest interrupted assistant message can resume; a live request must stop, or its heartbeat must be abandoned for ten minutes first. Resume reuses the original turn and daily allowance. Temporary chats are excluded. Background local task/research runs now have encrypted checkpoints and explicit Resume saved progress; see [workspace additions](docs/WORKSPACE_FEATURES.md). Neither mode guarantees exactly-once external inference.

Daily quotas default to 200 chat requests and 20 background-task runs per user. Set Laravel `CHAT_DAILY_LIMIT=200` and `TASK_DAILY_LIMIT=20` (or your preferred positive values), refresh config and restart workers. Existing deployments that previously set these values to zero must update them to enable limits. A deep research turn consumes one chat request; its internal searches, page reads, planning calls and answer continuations do not consume additional daily requests. Public API burst protection, authentication, ownership, user Stop, concurrent-turn protection and URL safety remain active. The private, secret-and-lease protected status/tool/finalize calls do not consume the public API burst allowance, so a running research turn is not cut off by its internal call count. Other product limits such as media quotas and file sizes are separate.

For long research, the Node host must support long-lived responses; static hosting cannot run this path. Set ingress/SSE timeouts and PHP/queue worker duration to suit your infrastructure. The frontend chat proxy has no fixed overall timer. NVIDIA calls have a 110-second timeout per individual planning/generation request. Background jobs declare no total application timeout; run the `tasks` worker with `--timeout=0 --tries=1` and configure queue visibility/retry_after longer than your operational job duration. A hosting platform may still terminate the process. No live search/NVIDIA verification was made without deployment credentials.

Official search API: https://docs.searxng.org/dev/search_api.html

## Team workspace, MCP and live conversation

Workspace now includes Teams, Connectors and Live. Team documents/discussions use membership and revision checks; private chats require reviewed snapshot consent before sharing. MCP tools use operator-reviewed endpoints, encrypted personal credentials and per-call approval. Live uses continuous microphone speech detection, private ASR, streamed chat and browser speech with optional sampled camera/screen observations. Billing is excluded.

See [setup, scope and verification](docs/COLLABORATION_AND_LIVE.md) before enabling the live runtime or external connectors.

## Administrator accounts

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in the server environment, then run `php artisan db:seed --class=AdminSeeder --force` after migrating and clearing stale config. Optional `ADMIN_NAME` and `ADMIN_AVATAR_PATH` customize the first profile. No default password is included, and reseeding never resets or promotes an existing account.

In the admin panel, **My profile** edits your name/photo and supports password or verified email changes. **New admin** creates another administrator with an optional image after confirming your current password and enabled 2FA. See [administrator setup](docs/ADMIN_ACCOUNTS.md).
